# Swatkinson's Claude Code Toolkit

_Version 0.4.0_

## Install

```
/plugin marketplace add swatkinson/swatkinson-cc-toolkit
/plugin install swatkinson-toolkit
```

To update later:

```
/plugin marketplace update swatkinson-cc-toolkit
```

The `/plugin` menu shows when a newer version is available (driven by the `version` in the plugin manifest).


## What's inside — `swatkinson-toolkit`

### Skills
| Skill | What it does |
|-------|--------------|
| `handle-it` | End-to-end orchestrator: tracked issue (or freeform feature) → plan → implement → draft PR → review⇄fix loop (5/5) → CI + preview → auto-test → your manual review → ready-for-review. **Project-generic** — reads all project specifics from `.claude/handle-it.md`. |
| `claudecodile-review` | 🐊 Iterate-until-5/5 in-house review⇄fix loop on a PR. Opus reviewer posts P#-tagged inline comments with suggested fixes; Sonnet fixer applies them. Standalone, or delegated to by `handle-it`. Reads its verify gate + hard-rule files from the same `.claude/handle-it.md`. |
| `handle-it-project-setup` | Scans a repo (build scripts, CLAUDE.md/AGENTS.md, CI workflows, available tracker tools) and generates the `.claude/handle-it.md` config that makes `handle-it` and `claudecodile-review` work on that project. Run this once per repo. |
| `issue-watcher` | Live, self-refreshing dashboard of your active Linear issues. |
| `skill-evaluate` | Retrospective self-evaluation of a skill run, scored against a 6-dimension rubric. |

### Agents (spawned by the skills)
`claudecodile-reviewer`, `claudecodile-fixer`, `handle-it-shipper`, `handle-it-investigator`, `handle-it-test-runner`, `issue-watcher-scanner`.

## Prerequisites

These skills were built for my workflow and lean on tools/plugins beyond this one. Install/configure these or the affected skills won't fully work:

- **A project config — `.claude/handle-it.md`** — `handle-it` and `claudecodile-review` are project-generic and read every project specific (verify gate, worktree command, tracker, branch naming, CI/preview, hard-rule files, migration tooling) from this file. Run **`/handle-it-project-setup`** once per repo to generate it. Without it, those skills will prompt you to create it.
- **An issue tracker (optional)** — `handle-it` supports Linear (via the Linear MCP server), GitHub Issues (via `gh`), Jira, or **no tracker at all** (freeform mode). The config declares which. `issue-watcher` (and its scanner agent) are still Linear-specific.
- **[`agentsystem-core`](https://github.com/AgentSystemLabs/core) plugin** — the default implement/PR/conflict/CI-fix engine skills (`agentsystem-core:ship`, `:open-pr`, `:resolve-conflict`, `:fix-pr-tests`). The config's **Engine skills** section can point at alternatives.
- **`diagnose`, `code-review`, `simplify` skills** — `handle-it`/`claudecodile-review` invoke these for the investigate and review passes. `diagnose`/`code-review` come from [Matt Pocock's skills toolkit](https://github.com/mattpocock/skills).
- **GitHub CLI (`gh`)**, authenticated — all PR operations.

`skill-evaluate` is the only fully standalone skill — no external prerequisites.

## Notes on portability

- **Project specifics are no longer baked into the skills.** `handle-it`/`claudecodile-review` hold zero project facts; everything lives in the per-repo `.claude/handle-it.md` (generated by `/handle-it-project-setup`). The same engine runs on a Bun/TanStack repo, a .NET solution, or an AutoCAD plugin — only the config differs. The engine also self-corrects the config when a value proves wrong at runtime.
- Some skill bodies reference paths like `~/.claude/skills/...` and `~/.claude/agents/...` for orientation. After install via this plugin the files actually live under the plugin's directory; those references are documentation only and don't affect execution.
- `issue-watcher` is still tuned to my Linear + repo conventions — review and adjust for yours.

## Repo layout

```
.claude-plugin/marketplace.json     ← marketplace manifest (this repo)
plugins/swatkinson-toolkit/
  .claude-plugin/plugin.json        ← plugin manifest
  skills/<skill>/SKILL.md           ← + REFERENCE.md per skill
  agents/<agent>.md
scripts/sync-version.ps1            ← keep the version in sync across the 3 files
```

## Releasing

The version appears in three places that must stay in sync — `plugins/swatkinson-toolkit/.claude-plugin/plugin.json` (the source of truth), `.claude-plugin/marketplace.json`, and the subtitle at the top of this README. `scripts/sync-version.ps1` keeps them aligned:

```powershell
pwsh scripts/sync-version.ps1            # check: reports drift, exits 1 if the three disagree
pwsh scripts/sync-version.ps1 -Set 0.2.0 # bump: writes the new version to all three
```

Run the check before tagging a release (or wire it into a pre-commit hook / CI step).
